# Plan: every Ring API field in a structured DB column

Rule: a value kept only in a `*Json` column is NOT in the DB. Every response field needs a typed column or a child row. Generic concepts go in provider-agnostic tables; Ring-only concepts go in `Ring*` tables, preferably 1:1 child tables, not more columns on `Devices` (already 77 columns).

Reviewed by a Sonnet agent; its corrections are folded in below.

## Done (all merged to `wip`)
- Selftester ignores `*Json` columns and reports unmapped response fields per endpoint (name matcher, see Batch 0).
- `account-monitoring-status`: `RingAccountMonitoringStatus` + `RingAccountMonitoringPlan`.
- Device `features`: `RingDeviceFeatureState`, `RingDeviceFeatureReason` (renamed with a data-preserving `RenameTable` migration, plus unstored-value logging in the features parser; null values are not logged), 20 `DeviceFeatures` columns.

## Rules for every batch
- Failing test first (record the red run), sanitized fixture, client model keeps unknown keys, parser/mapper, persister replace-on-sync (null object leaves rows untouched), EF config, `dotnet ef migrations add`.
- Before `migrations add`: merge the latest `wip`. If the snapshot conflicts, delete the new migration and Designer, restore the snapshot from `wip`, regenerate. Never hand-merge the snapshot.
- When two unmerged branches each add a migration: merge the first into the second, delete the second's migration and Designer, restore the snapshot from the FIRST branch's commit (not the merged one; a snapshot that already contains the second model makes `migrations add` produce an empty migration), `dotnet build`, then regenerate. `dotnet ef migrations remove` does not delete the files reliably. Verify with `InitialCreate_Schema_MatchesCurrentModel` and `dotnet ef migrations has-pending-model-changes`.
- Run MTP test projects with `dotnet test --project <csproj>` (global.json requires the Microsoft Testing Platform); include Data.Core tests whenever `VideoForensicsDataClient` or `DeviceDetailFields` change.
- Lite gate (a new entity name must also pass `Ui.Shared.Tests` and a `VideoForensics.WebApp` build; a name collision with a Razor page broke Ui.Shared tests through two merges): build touched projects, run the full provider, database, sqlite migration and Ring common test projects. Then commit, merge to `wip`, push `origin wip`.
- Types for fields null in every sample are guesses: use nullable string unless the shape is evident, and log the first non-null value (Info, device name not GUID, message and exception type only, no stack trace; Error level on a parser exception) so the guess can be fixed.
- No new `*Json` column or `MetadataJson` write. If a client model change breaks the Ring API tester or MAUI, update CLAUDE.md and the commit message.
- Existing `*Json` columns on `Devices` (`MetadataJson`, `SettingsMetadataJson`, `MotionSnoozeJson`, `LightSettingsMetadataJson`) conflict with the providers rule. Each batch that stores a group's keys in rows must stop writing that group to the JSON column; final cleanup drops the columns.

## Working rules (cost and process)
- Subagents: `haiku` for mechanical batches whose spec is complete (tables, columns, parser entries, map entries, tests from a given list). `sonnet` only for design, migration-sensitive or review work, with the criterion named before spawning. Verify every result yourself.
- One agent at a time per shared file set; one `dotnet` build or test at a time; no full-suite runs while another build is active.
- Keep large JSON and file dumps out of the main thread (use scripts that print counts).
- Every batch updates `field-map.json` for the paths it persists and shows the unmapped count dropping.

## Verification (proves "in the DB, not JSON")
1. Work on a copy of the live DB; run the app against the copy so migrations apply; never mutate the live baseline.
2. Unit test: every leaf path in each sanitized endpoint fixture, including empty arrays and arrays of scalars, has a map entry or an explicit "not data" reason (`FieldMapFixtureTests`).
3. **Round-trip test (done): `FieldMapRoundTripTests`** in `src/utils/selftest/tests`. It builds the real data layer (`AddVideoForensicsDataLayer` + server core), migrates a temp SQLite file with the real EF migrations (`DatabaseInitializer`), seeds the rows the download path creates (account, location, devices with time zone and detail fields), then runs the real sync once against a stub HTTP session: `RingDeviceDiscoveryService.GetLocationsAsync` (device list, config gate with profile, ringtones, light groups, location mode, mode settings, sharing, monitoring status, device settings per doorbot and stickup cam, location metadata and details, all event feeds) plus `RingDeviceHealthCapture` per device. Responses are the sanitized shape fixtures in `src/utils/selftest/tests/fixtures`, with each placeholder replaced by a distinct fake value (numbers, strings, date strings, flipped booleans; ids, location id, health units and a few parsed strings set to realistic fake values), so a value in the wrong column or on the wrong device differs from its neighbours. `FieldMapValueVerifier` (`src/utils/selftest/src`, implements `IFieldValueVerifier`, reads SQLite through `SqliteDbValueSource`) then walks every response leaf, resolves it through the field map and compares it with the column by value:
   - A leaf is checked against the values stored in that column for the same device (the table is tied to a device by a `DeviceId` property or a foreign-key chain to `Devices`; other tables are checked against all their rows). Array elements are matched as a multiset, since child rows carry no response index. A leaf whose column holds another endpoint's value (device list vs device-settings body, the later write wins) is counted as shadowed, only when that other value matched.
   - Types: bool vs 0/1, ints, doubles within 1e-5 relative, ISO date strings vs UTC `DateTime`, epoch ms/s vs `DateTime`, numbers and text (a documented conversion, counted separately), zone `enabled`/`disabled` vs 1/0, and the derived `StatusAtUtc` / `BatteryTempCelsius` through `RingHealthUnits`. No trimming.
   - Report: matched (after conversion), mismatched, missing row, shadowed, and not evaluated by reason (`Rows:` entries, `NotData`, null in the response, empty container, unmapped, endpoint not synced) per endpoint. Mismatch text names the path, `Table.Column` and value kinds; values are shown only when numeric, boolean or short plain text.
   - The test fails on any mismatch or missing row. Guards: the report must compare more than 800 values and every main endpoint must match something; tampering with a stored value, or deleting a table's rows, after the sync must be reported.
   - Limits: it proves each mapped fixture value reached its column, not that no stale or extra rows remain (replace-on-sync correctness is covered by the persister tests). A shared column is only checked against whichever endpoint's value is stored (shadowed leaves). Only the endpoints the sync calls are fed: `doorbot-health`, `chime-health`, `shared-users`, `linked-chime-doorbots`, `snapshot-timestamps`, `signalling-ticket`, `active-dings` and `amazon-key-locks` are counted as not synced (there is no sync caller for them yet). Leaves that are null in the fixtures, `Rows:` entries and `NotData` are not compared. The download path's own writes (device rows, `Devices.Name`, `TimeZoneId`, `Locations.Name`) are seeded by the test setup with the same calls, so those columns prove the harness, not the sync. Fixture values are fakes shaped like the saved responses; a type the real response has but the fixtures lack (for example a column whose parser needs a real format) is only as good as the override in `FieldMapRoundTripTests.Diversify`. `VF_ROUNDTRIP_KEEP_DB=1` keeps the synced database and the served responses in a temp folder (path in `%TEMP%f-roundtrip-last.txt`).
4. `--verify-db` repeats the value comparison against the real DB (not wired yet: `FieldMapValueVerifier.Verify(map, outputDir)` already reads a selftester output folder; it needs the CLI option, a read-only connection to the DB file and the same per-device grouping). Done means unmapped = 0 and mismatches = 0.
5. Guard test: no new `*Json` column / `MetadataJson` write.
